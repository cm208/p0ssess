Claude stays in charge.

p0ssess is a Claude Code plugin. Its Predictive Model Engine scores every model for each job, Claude included. When another model is good enough and cheaper, or can do what Claude can’t, Claude hands the work over through OpenRouter and checks it. You see one line.

On Pro, Max and Ultra it watches your Claude usage, and as you near your limit it hands off more so you can keep going.

Works with any Claude plan (Pro, Max, Team or Enterprise) or an API key. Other models bill to your own OpenRouter key.

claude --plugin-dir /path/to/p0ssess

The Predictive Model Engine

Every model that could do a job, Claude included, gets a confidence score out of 100: a cautious estimate that its result will be accepted, from licensed benchmarks, the use-case research and your own history.

Each severity has a gate. Below it, a model isn’t considered. Critical work stays with Claude unless your rule names a model.

SeverityFor exampleGateA mistake costs
TrivialRenames, log summaries, captions20$0.01
RoutineTest drafts, transcripts, bulk edits35$0.10
ImportantFeatures that ship, migration plans60$1
CriticalAuth, firewalls, production, money80$10

Above the gate, the lowest total wins. Total = the call, plus the Claude time it uses or saves, plus the risk of a redo.

Media Claude can’t watch

Claude can’t watch video or hear audio, so p0ssess sends the file to a model that can. On real calls, Gemini 3.8 Flash described a ten-second clip for $0.0067 and Whisper transcribed sixteen seconds of speech for $0.0002.

Tedious code, handed to a coding agent

For chores the tests can check, a relay agent runs a cheap coding model in its own sandbox, on a separate git worktree. Claude reads the diff and runs the tests before anything lands. Work that edits your code always asks first.

When your Claude usage runs low

On Pro, Max and Ultra, p0ssess reads the 5-hour and weekly usage Claude Code reports to the status line. Early in a window Claude’s time is cheap, so it keeps the work. Near the limit the same job goes out.

Rules in your own words

Say “only use gemini-3.8-flash for video”. Claude shows the rule in one line and saves it when you say yes. A standing approval lets repeats of a job run without asking, up to a price. A cloned repository’s rules can only tighten yours.

The sandbox

Agent work runs in OpenCode inside a rootless podman pod per session. It sees the repository read-only plus its own worktree, and no home directory, keys or credentials. Firewall rules loaded from outside the pod block your network, Tailscale and the host.

Your OpenRouter key stays in a proxy the model never sees. Shell commands get no network unless you allow it for a project. Every limit is checked by the tool that spends.

An independent review before release found a host-escape bug through a tampered worktree. It is fixed and tested.

What it won’t do

  • Patch or preload into Claude Code.
  • Send prompts to providers that train on them.
  • Spend past your monthly cap.
  • Create a rule or a standing approval on its own.
  • Send secrets, or anything from a repository marked .p0ssess-private.
  • Read, store or relay your Claude credentials.
  • Phone home. History stays local, without prompt text.

Try it

Private for now; releases are coming. You need Claude Code 2.1.319 or later and an OpenRouter key. Release archives carry the binary; a checkout builds it with Go 1.27. The agent sandbox needs Linux with rootless podman.

claude --plugin-dir /path/to/p0ssess

Put the key in ~/.config/p0ssess/secrets/openrouter_key (mode 0600) and run /p0ssess:p0ssess-me. Settings changes wait for your yes; p0ssess setup undo reverts them.

Usage-aware routing needs the p0ssess status line, which /p0ssess:p0ssess-me offers to install. On other plans, Claude is priced at API rates unless you set your plan. On Team and Enterprise, admins can block plugins loaded with --plugin-dir and restrict which plugins and tool servers you can use; check whether code may go to other providers.
