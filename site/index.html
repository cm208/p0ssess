Claude stays in charge.

p0ssess is a Claude Code plugin. Its Predictive Model Engine scores every model that could do a job, Claude included. When another one is good enough and cheaper, or can do what Claude can’t, Claude hands the work over through OpenRouter, checks the result, and carries on. You see one line.

claude --plugin-dir /path/to/p0ssess

The terminal replays a Claude Code session for each part of this page. Here p0ssess has nothing to say, which is how it spends most of its time.

The Predictive Model Engine

Every request that could leave Claude goes through it, and every model that could do the job is scored the same way, Claude included. It comes down to a score, a gate and a price.

A score out of 100

Each candidate gets a confidence score out of 100: a cautious estimate of how likely its result is to be accepted. It starts from licensed benchmarks and public usage data, and moves with your own history of what you kept and what Claude had to redo.

A gate for every severity

Claude rates each request from trivial to critical. Every level has a gate, and a model has to score at least that much to be considered at all.

SeverityFor exampleGateA mistake costs

Critical work also stays with Claude unless you write a rule that names a model for it.

Then the lowest real cost wins

Among the models that clear the gate, the engine picks the one that costs least overall: the price of the call, the Claude usage it spends or saves (worth more as you near your plan’s limit), the cost of handing the work off and checking it, and what a mistake would cost at that severity. Claude makes the final call, and your rules and budget have the last word.

That is also why small jobs stay put. A hand-off costs Claude $0.04 to $0.12 of its own usage, so anything cheaper than that to do in place never leaves.

Media Claude can’t watch

Claude reads code, text and images. It can’t watch a screen recording or listen to a voice memo. When a prompt mentions one, p0ssess adds a single line of context, and Claude sends the file to a model that can, with a prompt and a price ceiling. Then it works from the answer.

On real calls, Gemini 3.8 Flash described a ten-second clip for $0.0067 and was the only model tested that got every detail right, sound included. Whisper transcribed sixteen seconds of speech for $0.0002. Nothing large goes out quietly: a video over the size or length limit stops and offers local ffmpeg steps (downscale, keyframes or segments), and Claude says which one it picked.

Tedious code, handed to a coding agent

Ask for a chore, like moving every handler to a new router API, and the engine looks for a cheap coding model whose work the tests can check. A small relay agent runs that model in OpenCode, in the background, in a sandbox pod of its own, on a separate git worktree. What comes back is a diff. Nothing lands until Claude has read it and run the tests.

Work that edits your code always asks first. In testing, DeepSeek V4.1 Flash finished small coding tasks for $0.001 to $0.005 each. The hand-off itself took $0.04 to $0.12 of Claude’s usage, which is why only jobs bigger than that go out.

A second opinion from another family

Before a merge, ask for a review from outside Claude’s own family. The engine looks for a model that is good enough at code review and costs least; for a typical diff that was GLM-5.3-Flash, at an estimated $0.002. Claude checks each finding against the code, fixes what holds up and says what it skipped. The review adds to Claude’s own and never replaces it.

For important changes, Claude can also offer reviews from two other families at once, with their cost, before you decide.

Some work stays with Claude

When a request is critical, the gate decides before price does. Ask for a firewall change on a cheap model and Claude says so in one line, then does the work itself. The tools that spend enforce the same gate, whatever Claude decides.

Small work stays too, without a word: a rename costs Claude less to do than to hand off. If a rating looks wrong, say so in plain words and Claude uses yours.

Rules in your own words

Say what you want: “never use grok”, “only use gemini-3.8-flash for video”, “keep this repo on Claude”. Claude writes the structured rule, shows it to you in one line, and saves it when you say yes. A rule can cover the session, the project or everything, and it can expire.

A standing approval pre-approves a kind of job up to a price. Once one covers a job, repeats run without asking and still get their one line. p0ssess may suggest an approval after you’ve said yes to the same thing a few times. It never makes one on its own.

A rules file that arrives inside a cloned repository can only tighten your limits. Anything that would loosen them is ignored, and you’re told once.

A ghost in the status line

p0ssess adds one segment after your own status line, and shows nothing at all until something has happened that day.

  • Idle, spent todayᗣ p0ssess $0.14 today
  • Workingᗣ p0ssess 2 running $0.14
  • Near the budgetᗣ p0ssess $8.10 of $10 this month

Muted when idle, a little brighter while something runs, amber near your budget. Never red, never animated.

/p0ssess:p0ssess-me walks through the budget, your Claude plan and privacy, one question at a time, then opens a local page with spend against each limit, recent hand-offs, what it has learned, your rules and your settings. The page listens on 127.0.0.1, loads nothing from the network, and stops after two hours.

The sandbox

Multi-step work runs in OpenCode inside a rootless podman pod. Each session gets its own pod, created on its first run and removed when the session ends, so no run can see another’s files or transcript. Only the repository is mounted, read-only, plus that session’s worktree for edits. There is no home directory, no SSH key and no credential inside. OpenCode can reach the internet, but nftables rules loaded from outside the pod block your local network, Tailscale and the host.

Your OpenRouter key lives in a proxy container next to the agent, which the model never sees. Every shell command the model runs gets fresh namespaces and a scrubbed environment, so by default it has no network at all. You can let one project’s commands download packages; they then reach public sites through a filtering proxy that refuses everything else. A command outside the task’s allowlist pauses the run and comes back to Claude, which can allow it once or refuse.

Rules, stakes, privacy and every spending limit are checked by the tool that spends, not left to Claude’s judgment. Each call’s maximum is reserved before it goes out, so parallel calls can’t overshoot.

Before release, an independent review found that a delegated edit task could run code on the host through a tampered git worktree. That is fixed, with a regression test, along with the review’s other high-priority findings.

What it won’t do

  • Patch, preload into or otherwise modify Claude Code.
  • Send prompts to providers that train on them. Every call says so to OpenRouter, and zero-retention mode is one setting away.
  • Spend past your monthly cap.
  • Create a rule or a standing approval on its own.
  • Attach files that look like secrets, or send anything from a repository with a .p0ssess-private file.
  • Read, store or relay your Claude credentials.
  • Phone home. There is no telemetry. The history it learns from stays in local files and never holds prompt content.

Built from 104 use cases

The engine was built from 104 researched use cases, each backed by public evidence. About half are grounded in OpenRouter usage data, the other half in what Claude Code can’t do or does expensively. Each lists a recommended model, alternatives with Claude on equal footing, a severity, an expected cost, and how Claude checks the result. A few of them:

Every number comes from data whose license allows reuse, with its source and date: OpenRouter’s public model list and Data API (CC BY 4.0), LMArena’s leaderboard dataset (CC BY 4.0), the benchmarks Epoch AI runs itself (CC BY 4.0), and models.dev (MIT) as a cross-check. Where no clean benchmark exists, as for audio and video, the engine says so and learns from your own outcomes.

Sometimes the market and the evidence disagree. Cheap flash models run a 10–49-turn Claude Code session for a median $0.027 on DeepSeek V4.1 Flash, against $0.534 on Sonnet 5.5. On LMArena’s agent board, Opus 5.5 scores 0.201 and DeepSeek V4.1 Flash 0.024. The engine follows the evidence and treats agentic hand-offs as a priced risk.

Try it

The repository is private for now, and public releases are coming. With a checkout, start Claude Code with the plugin loaded in place:

claude --plugin-dir /path/to/p0ssess

You need Claude Code 2.1.319 or later, and an OpenRouter API key. Release archives carry the binary for Linux and Apple silicon Macs, checked against SHA-256 sums before it runs; a plain checkout builds it with Go 1.27 or later, offline, in a few seconds. The sandboxed agent path also needs Linux with rootless podman. Without it, media and one-shot jobs still work, macOS included.

Put the key in ~/.config/p0ssess/secrets/openrouter_key with mode 0600, then run /p0ssess:p0ssess-me. It asks about your budget, plan and privacy, and offers each change to Claude Code’s settings only after you say yes. p0ssess setup undo reverts them all.

claude ~/shop-web
