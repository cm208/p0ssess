If you pay for Claude at work, some of what you pay Claude’s rates for is repetitive: writing tests, sorting tickets. p0ssess sends that work to a cheaper model under a rule you set, while Claude stays in charge and checks the result. This page has the measurements, the method, and the jobs where it didn’t pay.

How it was measured

The design was written and committed before the first measured run, including what would count as a win. This is a summary of it, with what changed afterwards and why.

The question

Does Claude Code with p0ssess, and a rule that sends one kind of repetitive work to a cheaper model, cost less for each correct answer than Claude Code alone, at the same quality?

The jobs

We built repetitive jobs of the kind a team hands Claude Code day after day: sorting support tickets, pulling fields from invoices, triaging incident logs, translating interface strings, finding bugs in review, writing unit tests, extracting contract terms, normalizing product listings and routing voicemails.

Every dataset was made for the benchmark by a generator with a fixed seed, so the right answers are known by construction, and every answer is graded by a script, never by a model. None of it is customer data.

One run

A run is one headless Claude Code session, version 2.1.323, handed the whole batch the way a team member hands Claude the day’s work. Each starts from an empty configuration, with no plugins, memory or instructions file. The prompt is the same both ways and never mentions models, cost or delegation.

Runs alternate between the two setups, so the time of night affects both alike. A run that crashed for an infrastructure reason was rerun and logged. A run where Claude or p0ssess simply did the job badly was kept.

The two setups

Claude alone is stock Claude Code. It may use its built-in tools and its own subagents. Claude with p0ssess adds the public p0ssess 0.6.0 plugin and one rule: always send this kind of work to one named model. The model for each job is the engine’s own top pick that isn’t Claude, chosen before any run. Nothing was picked by hand.

In 0.6.0 that rule limited which model could be used but didn’t by itself make Claude delegate, so the p0ssess runs also carried it as one line of standing instructions, where a team would write one: “Team rule (p0ssess): always send unit test writing to deepseek/deepseek-v4.1-flash-1017.”

What it costs

Claude’s cost is what Claude Code reports for the session at API list prices, from exact token counts. It includes every Claude token: the model in charge, the Haiku relay and anything else Claude ran. The p0ssess runs add what OpenRouter charged for the other model. Subscription plans are not modeled.

What counts as a win

All four must hold, for at least three runs each way on the same data. The most expensive p0ssess run has to cost less for each correct item than the cheapest Claude run. Its average accuracy has to be within three points of Claude’s, and its worst run within five points of Claude’s worst. And every p0ssess run has to have actually delegated.

A win goes in an ad only if it is also at least twice as cheap on average. Jobs that fail are reported here with their numbers.

The control: Claude’s own cheap model

A skeptic’s first question is whether Claude Code’s own delegation does the same thing, since Claude Haiku 5.5 is cheap too. So on unit tests we ran a third setup: Claude alone, with one sentence added to the prompt telling it to hand the bulk of the work to a Haiku subagent and check what comes back. That cost $0.60 to $0.71 a run. The p0ssess runs cost $0.27 to $0.30, which is 2.2 times cheaper with no overlap, and every test file passed in both.

What changed along the way

Each change was written into the design when it was made, with its reason, and none changed a criterion after seeing the result it decides.

Headless runs have nobody to answer a question, so when a session stopped to ask one, the harness answered “Yes, go ahead and finish”, at most twice, in every setup. Claude Code pays a fixed cost for each session whatever the work, so ticket triage was also run at a day’s volume of 300, and both sizes are reported.

Voicemail routing was added as a ninth job after the first runs. Its first runs were thrown out and repeated, because a bug in the harness had kept Claude alone from installing a speech model. Runs on Gemini were priced again from their token counts at the highest list price for the model, because the first cost figures for them were too low. The raw transcripts of the earliest runs were lost to another harness bug. Their costs and grades had been recorded before that.

What we don’t claim

We don’t claim anything about translation quality, since that job grades rule-following only. We don’t claim anything about subscription plans, since Claude is priced at API list price. And we don’t claim these numbers are yours: the datasets are constructed, and your work will differ. That is what Pro’s savings report is for.

And the jobs Claude can’t do alone

Claude can’t watch a video or hear a recording. It has a workaround for each: it pulls still frames with ffmpeg, or installs a local speech model. p0ssess sends the actual file to a model that takes it. Each test here is one file, run both ways.

Then measure your own work

The runs above are ours, on data we built. With Pro you measure your own work the same way and get a report you can forward.

Calibration

Calibration runs built-in tasks with known answers on your own OpenRouter key, plus your own samples if you add them. It shows the cost before it starts, and the results tune which model p0ssess picks for each kind of job.

The savings report

For each kind of task, the report shows cost per correct answer and time, Claude alone against Claude with p0ssess. The Claude side is given in API dollars and as the share of your weekly limit saved. It is a local page, with a PDF export for whoever asks what the tool is worth.

For a team

Team is Pro for every seat, with an org on top. An owner sets the rules once and they reach everyone. A member’s own rules can only make them stricter. Each member gets a share of the monthly budget, and a spend dashboard shows the owner where it went.
