What the cloud sandbox does with your code

Pro’s cloud sandbox runs agent work on a hosted machine, so it has to receive some of your code. This page says what is sent, what is kept and what is logged.

Five commitments

  1. Only files git tracks are uploaded (up to 200 MB per session).
  2. Files that look like secrets are skipped, and repositories with a .p0ssess-private file are never sent.
  3. Everything is deleted when the session ends. Nothing is kept between sessions.
  4. No content is logged.
  5. The service runs in one US region at launch.

How it works

Your OpenRouter key never leaves your laptop

The sandbox sends each model request back over the session’s one encrypted connection. Your laptop adds the key, checks the run’s cost cap and forwards the request.

What the sandbox can reach

By default the sandbox can reach only package registries: npm, PyPI, crates.io, the Go module proxy and Maven Central. Full internet access is opt-in, per project.

What it learns about your machine

Your laptop’s folder path is never sent. Only the repository’s name is.

What the host logs

The host logs a session id, a shortened hash of the account id, the request type, the status, sizes, durations and why the session ended.

It never logs paths, file names, commands, prompts, model requests or diffs.

Files skipped as secrets

Files whose names look like secrets are left out of the upload. Each skipped file is named in the run’s result.

Show the names that are skipped
  • .env and .env.*
  • .envrc, .netrc, .pgpass, .git-credentials, .npmrc, .pypirc and htpasswd
  • SSH keys, such as id_rsa and id_ed25519
  • Files ending in .pem, .key, .p12, .pfx, .kdbx, .jks or .keystore
  • Names that start with credentials
  • Names with secret or secrets as a word
  • Anything under .ssh, .gnupg, .aws, .kube or .docker

Outside the sandbox

This page covers the cloud sandbox only. What the plugin sends otherwise is in the privacy policy.
