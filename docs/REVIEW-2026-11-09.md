# Independent review — 2026-11-09

An adversarial review of p0ssess for a public release: security first, then
correctness of money and policy, then public-release quality. The reviewer did
not write the code. `go vet ./...` and `go test ./...` pass on Go 1.27.3; the
fixes below ship with tests. No live OpenRouter calls were made.

## Verdict

**Not ready to publish yet — one blocking item remains (B1), the install URL.**
The one critical security bug found (host code execution from the sandbox) is
**fixed** in this branch. The remaining blockers are the design-level trust and
budget-enforcement issues under "High" that should be decided before the repo
carries the author's name; none is a secret leak and privacy is clean.

Blocking for public release:

- **B1 (install).** `README.md` and `docs/INSTALL.md` still say
  `claude plugin marketplace add <repository URL>`. A stranger cannot install.
  Fill in the real public `owner/p0ssess`, and add `repository`/`homepage` to
  `.claude-plugin/plugin.json`. *(Left for the author: the public URL is not
  known to the review.)*
- **B2 (trust model, C1 below).** A cloned repo's `.p0ssess/rules.toml` is
  trusted policy and can loosen spending limits with no user action. Decide the
  trust model before release.
- **B3 (enforcement, H5 below).** The budget cap is the only limit the execution
  paths enforce; allow/deny lists, forbid/only rules, the stakes gate, per-task
  and daily limits, standing-approval ceilings and `privacy.mode=zdr` are advice
  to Claude, not enforced at the tool. A prompt-injected Claude can spend to the
  monthly cap on any model.

Privacy is clean: a grep of every tracked file and every git rev for home-network
and personal markers found only intentional hits (the author's name in LICENSE
and the manifests, RFC1918 ranges in the jail deny-lists, and fake test keys).
All commit authorship is `Christian Moore <me@christianmoo.re>`; no AI trailers.
The only private reference is the untracked git remote.

## Critical

### SEC-1. Sandbox escape → host code execution via a tampered worktree — FIXED

`internal/relay/files.go` (`worktreeDiff`, `git` helper).

An edit-mode task runs in a git worktree under `<repo>/.p0ssess/wt/`, and the
pod mounts both `<repo>/.p0ssess/wt` and `<repo>/.git/worktrees` **read-write**.
The per-session rules block the *edit tool* from touching `.git`, but a model's
*shell* command in edit mode (`cp`, `mv`, `sed`, `python3`, a redirection) can
write anywhere in its worktree, including the worktree's `.git` pointer file and
its admin dir's `commondir`/`config.worktree`. When the run ends the **host**
relay process runs `git -C <wt> add -A` and `git diff` on that worktree
(`worktreeDiff`) with no isolation. Git reads the attacker-controlled config and
runs whatever `core.fsmonitor` / `diff.external` / `core.hooksPath` names — on
the host, outside the sandbox, with the user's full environment.

Reproduced end-to-end: a worktree `.git` repointed at an in-tree fake gitdir
whose `config` sets `core.fsmonitor = "touch …; false"` executes that command
the moment the host runs `git add -A`. The same works through a rewritten
`commondir` and through `config.worktree` + `extensions.worktreeConfig`.

Impact: full host RCE from any delegated edit task (the model the user handed
work to, or a prompt-injected one). This is the single most serious issue for a
tool whose whole premise is running other models' output.

Fix (this branch): `worktreeDiff` now pins `GIT_DIR` and `GIT_COMMON_DIR` to the
real admin dir (under the read-only real `.git`) and `GIT_WORK_TREE` to the
worktree, so a tampered on-disk pointer or `commondir` cannot redirect git to
attacker config; every git call also runs with `GIT_CONFIG_NOSYSTEM=1`,
`GIT_CONFIG_GLOBAL=/dev/null` and `-c core.fsmonitor=false -c core.hooksPath=/dev/null -c core.pager=cat`
as defense in depth. Regression test
`internal/relay/worktree_test.go:TestWorktreeDiffIgnoresTamperedGitdir` tampers
all three vectors and asserts no host program runs while the real diff still
comes back. Fixed in this commit.

## High

### SEC-2 / H5. The execution paths enforce only the monthly cap — recommendation

`internal/server/server.go` (`RunDirect`, the `run` wrapper), `internal/relay`.

`recommend` applies the allow/deny lists, forbid/only rules, the stakes gate,
privacy mode and standing-approval accounting — but the `direct` tool and the
relay `run` tool accept any model and any `max_cost_usd` and check **only** the
monthly cap. Not enforced at the tool: `budget.toml` model/provider allow-deny,
forbid/only rules, the stakes-4 gate, `per_task_usd`, the daily limit, a standing
approval's per-run/count/total ceilings, and `privacy.mode = zdr` (the proxy
forces `data_collection=deny` but not zero-retention endpoint selection, which is
only sent when the caller passes `strict_zdr`). `.p0ssess-private` blocks
attached files but not a prompt-only `direct` call made from inside a private
repo (`RunDirect` never checks `paths.Private`).

Impact: all of this is advice to the main model. A prompt-injected or mistaken
Claude can route to a forbidden/expensive model and spend up to the monthly cap.

Cheap partial fixes worth taking now, in `RunDirect` (not applied — they change
behavior and want their own tests): force `StrictZDR` when the budget privacy
mode is zdr; refuse when `budget.ModelAllowed` fails or a global forbid matches;
refuse when `paths.Private(cwd)`; count standing-approval use from measured runs,
not only from outcomes Claude chooses to report. Full enforcement (stakes gate,
per-task/daily/approval ceilings at the tool) is a design decision.

### C1 / B2. A cloned repo's project rules are trusted and can loosen limits

`internal/rules/rules.go` (`ReadFile` never validates), `internal/pme/engine/engine.go`
(`RuleFiles` loads `<root>/.p0ssess/rules.toml`), `EffectiveBudget`,
`internal/server/server.go`.

A `.p0ssess/rules.toml` committed to a repository is loaded at **project** scope
and feeds `Decide`/`EffectiveBudget` the moment the user works in that repo. With
no user action a malicious repo can: raise the monthly cap and per-task limit,
turn the daily limit off (`daily_usd=-1`), add an unlimited standing approval
(`approve max_per_run_usd=1e6` → every option auto-approved), lift the stakes-4
gate (`allow target="delegation" max_stakes=4`), and steer routing with
`only`/`mix`. It cannot override the `budget.toml` allow/deny lists, change
privacy mode, remove `.p0ssess-private`, or beat a global forbid.

Design decision needed. Options: project scope may only *tighten* (take the min
of global/project for budget fields; ignore project `approve` and `max_stakes`);
or keep project rules outside the repo (`~/.config/p0ssess/projects/<hash>/`) or
behind a trust record keyed by path+hash. Separately and low-risk: run
`Rule.Validate` on every rule read and drop invalid ones (today unvalidated file
rules admit `max_stakes=99`, negatives, and — before this branch — NaN/Inf).

### H1. Non-finite caps turned off every limit — FIXED

`internal/budget/budget.go`, `internal/pme/engine/ops.go`, `internal/rules/rules.go`.

`monthly_usd = nan` / `per_task_usd = inf` passed validation, and every guard is
`spent + x > cap`, which is false when the cap is NaN — so all limits were off.
Reachable from `budget.toml`, `settings_set`, and (unvalidated) file rules.
Fixed: `budget.Validate`, the `settings_set` numeric parser, and `Rule.Validate`
now reject non-finite numbers. Tests:
`internal/budget/budget_test.go:TestValidateRejectsNonFinite`. The direct path's
`MaxCostUSD=NaN` and the CLI `--max-cost NaN` are still accepted (not fixed; part
of H5's tool-side enforcement).

### H2. Budget guards failed open on a read error — FIXED

`internal/server/server.go`.

Both the relay `run` guard and `RunDirect` used
`if st, err := eng.Status(…); err == nil && over {…}`: any unreadable or invalid
`budget.toml`/`engine.toml` made the cap check silently skip while `recommend`
correctly refused. Fixed: both now refuse the run when `Status` errors.

### H3. Check-then-spend race, no reservation — recommendation

`internal/server/server.go`. Spend is read from the ledger before a call and only
appended after it finishes, so N concurrent calls (parallel tool calls, several
Claude processes, relay runs that returned `still_running`) each pass the same
cap check and can overshoot by up to N × per-call. Bounded per relay run by
`max_run_cost_usd` ($0.50 default), unbounded across many direct calls. Fix is a
reservation ledger under `flock` (reserve before, release on finish, expire dead
PIDs) — a design change, not applied.

### H4. Missing or late cost recorded as $0 — recommendation

`internal/direct/chat.go`, `internal/direct/images.go`, `internal/relay/result.go`,
`internal/server/server.go`. Several paths record $0 or nothing for a billed
call: a failed `/generation` cost lookup → `CostSource="unknown"`, cost 0; an
early return on `saveImage`/image error before usage is folded in; a relay
`GetSession` failure leaving cost 0 while `Recorded=true`; relay runs that end in
the background after `still_running` and are never waited on (never recorded);
`RecordRun` errors ignored. Each lowers measured spend and loosens the cap. Fixes
(record a conservative figure when cost is unknown; fold usage before returning;
record on watch finish and shutdown; surface `RecordRun` errors) are small but
touch billing paths and want their own tests — written up, not applied.

## Medium

- **M1. The PDF-engine route skips the gate.** `internal/pme/score/score.go`
  (`engineOption`) never calls `gate`, the privacy check, `ModelAllowed` or the
  monthly check, so `engine:mistral-ocr` is offered at stakes 4 and under zdr.
  Clear fix; not applied.
- **M2. `allow target=delegation max_stakes=4` lifts the gate for every model**
  (`rules.go` `MaxStakesFor`), while `docs/ENGINE.md` says the rule must name the
  model. Code or docs must change.
- **M3. A second opinion is offered in a `.p0ssess-private` repo**
  (`internal/pme/engine/second.go`, `engine.go` never check `Private`).
- **M4. Session rules leak across sessions/projects.** `usage.go` `SessionFor`
  falls back to the most recent session anywhere, so one project's session-scoped
  rule (e.g. a monthly override) applies in an unrelated project. Remove the
  fallback.
- **M5. Budget rules ignore `use_cases`/`kinds`** (`rules.go`): "per-task $5 for
  video" silently becomes a global $5 per-task limit. Reject the scoping on
  budget rules or honor it.
- **M6. An unknown price estimates $0**, so `max_cost_usd=0` passes and
  `max_price` is omitted; a live image-price fetch can wipe the registry price.
  Refuse a paid route whose price is unknown unless the model is known free.
- **M7. The relay CLI `p0ssess run` bypasses the guards** and, on
  `still_running`, exits while the OpenCode session keeps running with no cost or
  runtime cap (its watch goroutines died with the process).
- **M8. The ledger failed open on corruption — FIXED.** A torn final line (crash
  mid-append) swallowed the next run, and a line over 1 MiB aborted the whole
  scan so spend read low and the cap failed open. Fixed: `Append` starts a fresh
  line when the file does not end in `\n`; `Read` skips overlong/garbage lines
  instead of aborting. Test:
  `internal/history/history_test.go:TestReadSkipsTornAndOverlongLines`.
- **M9. Docs state features that do not exist** (`docs/DESIGN.md`): reading
  Claude memory files for preferences (:106), a published evaluation set (:107),
  measuring progress-summary cost (:134), and a weekly registry-rebuild CI job
  (:163) — no code or workflow for any. Delete or move to a "Not built" list.
- **M10. Privacy wording vs. transcripts.** The ledger stores no prompt content,
  but the relay writes full task+output transcripts to
  `~/.config/p0ssess/runs/<id>/` and nothing prunes them. README now notes this
  (fixed in this branch); DESIGN/RELAY could say it too.

## Low

  (a future `created` means an approval's count/total never reset). **FIXED**:
  `RuleAdd` now clears both.

  exit check", "belong in a later milestone") — `docs/RELAY.md`, `docs/MEDIA.md`,

- **L3. `p0ssess-engine` identity leftovers.** `internal/pme/cli/cli.go` prints
  "p0ssess-engine 0.1.0" (vs the plugin's 0.2.0); `mcpserver` serverInfo and
  `registry/live.go` User-Agent say "p0ssess-engine"; `p0ssess engine mcp` serves
  a second, dead hand-rolled MCP server. Unify the version and drop the dead path.

  names (12, not the 13 in `setup.go`) that would break a manual install. Delete
  or document.
- **L5. "Read-only" mislabel.** `docs/INSTALL.md` and `commands/p0ssess-me.md`
  call the allowed engine tools "read-only", but `history_record_outcome` writes
  the ledger.
- **L6. Licensing notices for vendored/adapted code.** Vendored notices are
  present in `vendor/`, but nothing surfaces them and `scripts/build-release.sh`
  ships no NOTICE with binaries (Apache-2.0 §4(d), via yaml.v3, wants it). The
  copied `internal/opencode/testdata/openapi-2.2.5.json` (OpenCode, MIT) carries
  no attribution. Add a `THIRD_PARTY`/ATTRIBUTION line. Registry data is filtered
  and attributed, not mirrored — but `docs/DESIGN.md` "derived results only" is
  inaccurate for `openrouter_evals.json` (40 filtered raw rows); reword to
  "filtered to referenced models, attributed; never a full mirror". `aider_polyglot.json`
  ships 0 records yet is listed as "Used"; drop it or relabel.
- **L7. Config edge values** (`engine.toml`): `cash_headroom<=0` makes everything
  auto-approve; a negative `max_run_cost_usd` turns off the relay interrupt.
  Validate.
- **L8. Read-modify-write races** with no file lock on `rules.toml`,
  `budget.toml`, `usage.json` can lose a concurrent update (a lost forbid rule
  fails open). `flock`.
- **L9. `direct.Client.CallTool`** (`internal/direct/tool.go`) bypasses
  `RunDirect` (no cap, no ledger); exported and used only by tests. Delete or
  route through `RunDirect`.
- **L10. XDG / paths.** Relay state (`history.jsonl`, `sessions/`, `runs/`,
  `jails/`) lives in `~/.config/p0ssess` while the engine's lives in
  `~/.local/state`; two different files are both named `history.jsonl`. Consider
  moving relay state to the state dir and renaming the relay log.
- **L11. Dead code:** `jail.(*Jail).Healthy`, `opencode.(*Client).LastAssistant`,
  `mcp.Server.ToolNames`, `bench.Estimate.Upper`.
